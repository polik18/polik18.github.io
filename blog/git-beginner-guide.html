Git 是什麼？Git、Repo、Commit、GitHub 與常用指令教學｜新手入門指南

作者：小黃老師（C樂遊）・發表於 2026-11-12



Git 是什麼？Repo、Commit 又是什麼？新手必懂的版本控制完整教學

寫程式最怕什麼？不是遇到 Bug，而是修改後才發現原本的版本比較好，卻再也找不回來！如果你的電腦裡曾出現「最終版」、「最終版2」、「真的最終版」等資料夾，那麼 Git 絕對值得認識。這篇文章將用生活化的比喻，帶你一次搞懂 Git、Repository、Commit、Branch 與 GitHub 的差異，並透過實際指令練習，建立屬於自己的第一份版本紀錄。即使沒有程式開發經驗，也能逐步理解 Git 如何讓專案管理變得更有條理。

一、Git 是什麼？為什麼需要版本控制？

你有沒有這樣的經驗？花了一整個下午修改程式，原本正常運作的功能卻突然壞掉。想把程式改回昨天的樣子，才發現自己根本不記得改過哪些地方。

又或者，你為了避免類似情況發生，開始替專案建立大量備份資料夾，像是 project_v1、project_v2、project_final，到最後連自己都分不清楚哪個才是最新版本。

這正是 Git 想要解決的問題。

💡 一句話理解 Git

Git 是一套分散式版本控制系統（Distributed Version Control System），可以追蹤專案的修改歷史、比較不同版本，並協助開發者管理及整合程式碼。

如果把寫程式比喻成玩遊戲，Git 就像一套可以自行建立存檔點的系統。每當完成一個重要功能，都能留下紀錄。未來發現錯誤時，就有機會透過歷史紀錄找出問題，甚至讓特定內容恢復到之前的狀態。

不過，Git 比遊戲存檔更強大。它還能讓你知道誰修改了程式、什麼時候修改、修改了哪些內容，以及這次修改背後的目的。

🕒保留修改歷史

每次正式提交的版本，都能在歷史紀錄中找到。

🔎比較程式差異

快速了解哪些檔案與程式碼發生變更。

🤝支援多人協作

不同開發者可以分工開發，再整合成果。

🛟協助處理錯誤

透過版本紀錄追查問題，降低修改風險。

值得注意的是，Git 不只能管理程式碼。技術文件、網站原始碼、設定檔，甚至純文字筆記，都可以透過 Git 進行版本控制。只是對一般開發者來說，程式開發仍然是最常見的應用情境。

二、Repository（Repo）到底是什麼？

在學習 Git 的過程中，你一定會遇到 Repository 這個單字。它通常簡稱為 Repo，中文可以稱為「儲存庫」或「版本庫」。

你可以先把 Repo 想像成一個受到 Git 管理的專案資料夾。不過，真正重要的不是資料夾本身，而是其中保存的版本控制資訊。

假設你正在製作一個 Python 專案，資料夾裡面有 main.py、utils.py 和 README.md。一開始，這只是一個普通的專案目錄。當你在目錄中執行以下指令：

git init

Git 就會建立隱藏的 .git 目錄，用來保存 Commit、分支參照及其他版本管理所需的資料。這時，原本的資料夾就成為一個 Git Repository。

📁 Git Repository 結構示意圖
my-python-project/
├── .git/             ← Git 版本管理資料
├── main.py           ← 主要程式
├── utils.py          ← 共用功能
├── README.md         ← 專案說明
└── requirements.txt  ← 套件需求

Repo 又可以分成兩種常見類型：Local Repository（本地儲存庫）與Remote Repository（遠端儲存庫）。

比較項目本地儲存庫遠端儲存庫
所在位置自己的電腦其他電腦或伺服器
需要網路嗎？不一定，版本管理可以離線操作透過網路存取時通常需要
主要用途日常修改、Commit、管理版本跨裝置同步、共享及多人協作
常見情境Windows 上的 Python 專案託管在 GitHub 的專案

所以，Repo 並不是 GitHub 才有的東西。即使沒有網路，或完全不使用 GitHub，你依然可以在自己的電腦建立 Repo、修改程式，並保存 Commit 紀錄。

三、Commit 是什麼？跟一般存檔有什麼不同？

如果 Repository 是保存專案歷史的地方，那麼 Commit 就是 Git 中最重要的版本紀錄單位。

Commit 可以理解成：將暫存區中準備好的專案狀態，正式建立成一筆具有識別碼與歷史關係的版本紀錄。

例如，你正在開發一個 Discord Bot。第一天完成基本登入，第二天新增音樂播放，第三天修正播放錯誤。這三個開發階段，就很適合分別建立 Commit。

✨ Commit 版本時間軸
Commit A建立基本登入功能第一個可正常運作的版本
Commit B新增音樂播放功能在原有功能上持續開發
Commit C修正影片播放錯誤留下這次修正的歷史紀錄

每筆 Commit 通常包含提交者資訊、提交時間、說明訊息，以及當次專案狀態與前一筆歷史紀錄的關聯。Git 也會替 Commit 產生專屬的雜湊識別碼（Commit Hash）。

輸入以下指令，就能查看精簡的 Commit 歷史：

git log --oneline

畫面可能會出現：

a3f8c21 修正影片播放錯誤
b7e4d92 新增音樂播放功能
c1a6f03 建立基本登入功能

這些英文字母與數字，就是 Commit 識別碼的縮短形式，方便你辨認不同版本。

⚠️ Commit 不等於按下 Ctrl + S

在編輯器中儲存檔案，只是把修改寫入硬碟；建立 Commit 則是讓 Git 正式記錄一個版本。你可以一天存檔幾十次，卻只建立兩三筆 Commit。兩者不是同一件事。

另外，Git 並不要求每次修改都建立 Commit。比較理想的做法，是在完成一項有意義、容易理解的功能或修正後，再留下清楚的版本紀錄。

四、搞懂 Git Add、Commit、Push 工作流程

剛開始學 Git，最容易搞混的就是 git add、git commit 和 git push。其實只要理解 Git 的工作流程，就會發現三者各有不同任務。

🚀 從修改程式到同步遠端的四個階段
01｜Working Directory工作目錄

編寫、修改與儲存程式碼

02｜Staging Area暫存區

透過 git add 挑選要提交的內容

03｜Local Repository本地儲存庫

透過 git commit 建立版本紀錄

04｜Remote Repository遠端儲存庫

透過 git push 推送版本紀錄

流程示意：工作目錄 → git add → 暫存區 → git commit → 本地儲存庫 → git push → 遠端儲存庫

1. git add：挑選要提交的修改

假設你剛剛修改了 main.py，可以輸入：

git add main.py

這代表把該檔案目前的內容加入暫存區，準備納入下一次 Commit。如果想把目前目錄與子目錄下的新增、修改及刪除紀錄一併加入，則可以使用：

git add .

這裡有個重要觀念：add 並沒有真正建立版本，它只是決定下一次 Commit 要包含哪些內容。如果你在 Add 之後又修改了檔案，新的修改不會自動加入原本的暫存內容，還需要再次 Add。

2. git commit：正式建立版本

完成暫存之後，輸入：

git commit -m "新增使用者登入功能"

其中 -m 可以讓你直接撰寫 Commit 訊息。訊息越清楚，未來追查問題就越方便。這筆 Commit 會先存在本地儲存庫，因此就算目前沒有網路，通常也不影響建立 Commit。

3. git push：把版本推送到遠端

如果已經建立遠端儲存庫並完成分支設定，就能使用：

git push

將本地分支的 Commit 推送到遠端。請特別記住：Commit 是建立本地版本紀錄，Push 才是把版本送到遠端。如果尚未設定遠端位置、沒有權限，或遠端版本已經更新，Push 也可能失敗。

五、實戰教學：建立第一個 Git 專案

理解概念後，接下來就實際操作一次。以下以 Windows 的 PowerShell 與簡單的 Python 程式為例，帶你完成第一筆 Commit。開始前，請先從 Git 官方網站安裝 Git，確認終端機可以正常執行 git --version。

Step 1：建立專案資料夾

開啟 PowerShell，輸入：

mkdir hello-git
cd hello-git

這會建立名為 hello-git 的資料夾，並切換到該目錄。

Step 2：初始化 Repository

git init

看到初始化成功的訊息後，代表 Git 已開始管理這個專案。不同 Git 版本或設定下，初始分支名稱可能有所不同，常見名稱包括 main 與 master。

Step 3：設定 Git 作者資訊

第一次使用 Git，通常需要設定 Commit 所使用的名稱與電子郵件：

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

請將範例替換成你想使用的資訊。這些資料會寫入 Commit 中，並不是 GitHub 的登入指令。如果將 Commit 公開，相關作者資訊也可能被其他人看到。

Step 4：建立第一個程式

使用記事本或 Visual Studio Code，在專案資料夾中建立 main.py，並輸入以下內容後存檔：

print("Hello Git!")

Step 5：檢查狀態並加入暫存區

git status
git add main.py
git status

第一次執行 git status 時，通常會看到 main.py 是尚未追蹤的檔案。執行 Add 後再查看，就能觀察暫存區的變化。

Step 6：建立第一筆 Commit

git commit -m "建立第一個 Python 程式"

如果作者資訊設定正確，就能建立第一筆版本紀錄。接著輸入：

git log --oneline

你應該會看到剛剛建立的 Commit 與其縮短識別碼。

Step 7：修改程式，建立第二個版本

將 main.py 改成：

print("Hello Git!")
print("This is my second version.")

儲存檔案後，執行以下指令：

git diff
git add main.py
git commit -m "新增第二行輸出文字"
git log --oneline

git diff 可以顯示尚未加入暫存區的變更。完成第二次 Commit 後，歷史紀錄中就會出現兩筆提交。這表示你已經成功完成最基本的 Git 版本控制操作！

🎉 小練習

試著在程式中新增第三行文字，先使用 git status 查看狀態，再透過 git diff 比較修改。確認內容沒問題後才建立 Commit。反覆操作幾次，比單純背指令更容易理解 Git 的工作方式。

六、Git 與 GitHub 差在哪？Clone、Pull、Push 怎麼用？

很多人第一次聽到 Git，是因為看到了 GitHub。因此常常把 Git 與 GitHub 當成同一個東西，其實兩者的角色完全不同。

⚙️Git：版本控制工具

負責追蹤變更、管理 Commit、建立分支及合併版本。可以在自己的電腦離線使用。

☁️GitHub：線上協作平台

提供 Git Repository 託管，以及 Pull Request、Issue 與團隊協作等功能。

你可以把 Git 想成管理版本的工具，而 GitHub 就像是讓你與其他人共享 Git 專案的線上工作空間。除了 GitHub，也有 GitLab 等提供類似功能的平台。

git clone：將遠端專案複製到電腦

git clone https://github.com/example/my-project.git

Clone 通常用於第一次取得遠端專案。它不只是下載目前的程式碼，還會建立本地 Repository，取得相關版本資料，並通常將原始遠端儲存庫設定為 origin。上述網址只是示範，實際操作時要換成真實的 Repository 網址。

git pull：取得並整合遠端更新

git pull

如果團隊成員已經推送新的 Commit，你可以透過 Pull 取得遠端更新並整合至目前分支。它並非單純下載檔案，實際整合方式可能依 Git 設定採用 Merge 或 Rebase，必要時仍須處理衝突。

git push：推送自己的 Commit

git push

當你在本地完成修改並建立 Commit 後，就能透過 Push 將版本紀錄送到遠端。如果是第一次替新專案設定 GitHub，還需要先建立遠端 Repository 並完成連線設定。例如，在 GitHub 建好空白 Repository 後，可以依實際網址設定：

git branch -M main
git remote add origin https://github.com/YOURNAME/hello-git.git
git push -u origin main

這組指令適用於新建且尚未設定遠端的本地專案。請將網址改成自己的 GitHub Repository，並先完成必要的身分驗證。git branch -M main 會將目前分支重新命名為 main，而 -u 則會設定遠端追蹤關係。若遠端已有不同的初始 Commit，例如預先建立 README，可能需要先整合歷史，不能直接假設 Push 一定成功。

七、Branch 與 Merge：為什麼分支這麼重要？

假設你正在維護一個已經能正常播放音樂的 Discord Bot，現在想加入 Spotify 搜尋功能。但新功能還在實驗階段，你不希望修改直接影響原本的主要開發版本。

這時就可以使用 Git Branch，也就是「分支」。

🌿 Branch 的核心觀念

分支可以讓不同功能沿著不同的開發路線持續建立 Commit，等到開發與測試完成，再視需要整合。它不是複製一整份專案備份，而是透過 Git 的版本歷史與分支參照來管理不同開發方向。

例如，先建立名為 feature-spotify 的功能分支：

git switch -c feature-spotify

接著，你可以在這條分支上編輯程式，並建立專屬的 Commit。原本主要分支的歷史不會因為你在功能分支上提交內容，就自動被修改。

🌳 分支開發示意圖
main:             A ─── B ───────── C
                       \         /
feature-spotify:       D ─── E

A、B、C、D、E 代表不同的 Commit
示意圖為了方便理解而簡化，實際合併可能產生額外的 Merge Commit，也可能採用 Fast-forward。

完成新功能後，可以切換回主要分支，再將功能分支合併：

git switch main
git merge feature-spotify

不過，Merge 也不是完全沒有風險。如果兩個分支修改了同一份檔案中的相同區域，Git 可能無法自動判斷該保留哪一種內容，這就是所謂的 Merge Conflict（合併衝突）。

發生衝突時，需要開發者檢查衝突區域、決定正確內容，並完成後續合併。這是多人協作時很常見的情況，不代表 Git 故障。

八、初學者最容易犯的錯誤與安全提醒

錯誤一：以為 git add 就等於備份完成

Git Add 只是將內容加入暫存區，並不代表已經建立正式版本。若要留下可供日後查閱的歷史紀錄，還必須執行 Commit。即使已經 Commit，也不代表相關資料已經備份到其他電腦。若硬碟損壞且沒有其他副本，本地歷史仍可能遺失。

錯誤二：每次 Commit 都只寫 update

像是 update、fix 或 test 這類過度簡略的訊息，未來通常很難辨認修改目的。建議改成「新增會員登入驗證」、「修正 YouTube 播放錯誤」、「調整資料庫連線逾時設定」等具有明確意義的描述。

錯誤三：將 API Key、密碼或 Token 一起提交

這是非常需要留意的安全問題。開發程式時，經常會使用 .env 保存環境變數或金鑰，但這些內容通常不適合直接提交到公開 Repository。你可以建立 .gitignore 檔案，指定 Git 忽略尚未追蹤的特定檔案或目錄。

.env
node_modules/
__pycache__/
*.log

不過，.gitignore 不會自動移除已經被 Git 追蹤或寫入歷史的機密資訊。如果金鑰已經意外公開，應先視為憑證可能外洩，盡快撤銷或更換，再依情況處理儲存庫中的紀錄。

錯誤四：看到還原指令就直接執行

Git 確實能協助恢復版本，但不同指令的影響差異很大。例如 git revert 通常會透過新增 Commit 抵銷指定修改；git reset 則可能移動分支位置，而搭配 --hard 時還可能捨棄尚未保存的本地修改。

因此，初學階段應先熟悉 git status、git diff 與 git log，弄清楚檔案狀態與歷史紀錄，再學習具有還原或重設效果的指令。

九、Git 常用指令整理與常見問題

到這裡，你應該已經能分辨 Git、Repo、Commit、Branch 與 GitHub 的角色了。最後將常用指令整理成速查表，方便往後開發時隨時回來參考。

指令主要功能使用時機
git init初始化 Git 儲存庫開始管理新專案
git status檢查目前檔案狀態修改前後確認變動
git add .將變更加入暫存區準備建立 Commit
git commit -m "訊息"建立版本紀錄完成一項修改後
git log --oneline查看精簡歷史追蹤已建立的版本
git diff比較尚未暫存的修改檢查程式碼差異
git branch列出本地分支確認分支狀態
git switch -c 名稱建立並切換分支開發新功能
git merge 名稱合併指定分支整合功能成果
git clone 網址複製遠端儲存庫第一次取得專案
git pull取得並整合遠端更新同步團隊修改
git push推送本地 Commit分享版本紀錄

Q1：不會寫程式，也需要學 Git 嗎？

不一定，但如果你經常管理文字檔、設定檔、網站內容，或想了解開源專案的運作方式，Git 仍然很有幫助。它不限定特定程式語言，也不只服務軟體工程師。

Q2：Git 一定要搭配 GitHub 使用嗎？

完全不用。Git 可以獨立在本地電腦運作。GitHub 是額外提供遠端託管與協作功能的平台，而不是 Git 的必要條件。

Q3：Commit 越多越好嗎？

重點不是數量，而是每一筆 Commit 是否有清楚的目的。建議將有關聯的修改整理成有意義的提交，而不是每修改一個字就 Commit，也不要累積大量毫不相關的修改才一次提交。

Q4：使用 VS Code，還需要學 Git 指令嗎？

不一定要全部背熟。VS Code 內建原始檔控制功能，可以透過圖形介面檢視修改、暫存檔案及建立 Commit。不過，理解背後的 Git 概念仍然非常重要。當同步失敗、出現分支衝突或需要進階操作時，基本指令會讓你更容易找到問題。可以參考 VS Code 官方原始檔控制文件。

Q5：想把程式恢復到之前的版本，該怎麼辦？

可以先使用 git log 找出目標 Commit，再依需求選擇查看舊版本、恢復個別檔案或建立反向修正。不同還原方式會影響工作目錄或版本歷史，尤其是已經分享給其他人的 Commit，更應謹慎操作。

十、結語：先理解版本概念，再開始學指令

學習 Git 最重要的，不是第一天就背下所有指令，而是理解這套系統如何管理專案的歷史。

用最簡單的方式記住：Git 是版本控制工具，Repo 是保存專案版本的儲存庫，Commit 是正式建立的版本紀錄，Branch 是不同的開發路線，而 GitHub 是可以託管 Git Repository 的線上協作平台。

日常開發時，可以先從這個最基本的流程練習：

git status
git add .
git commit -m "完成某項功能"
git push

其中，最後的 Push 必須先完成遠端儲存庫與分支設定。若只是練習本地版本控制，前三個步驟就能讓你開始累積 Commit 紀錄。

不管你正在開發 Python 工具、Discord Bot、網站，還是準備投入大型軟體專案，Git 都能協助你把每次修改整理得更清楚。當你習慣在重要階段建立 Commit，就不再需要依賴「最終版_v3_真的最終版」這種令人崩潰的檔名了。

版本控制真正的價值，不只是能夠回顧過去，而是讓每一次修改都有跡可循，讓未來的開發更安全、更有條理。

📚 延伸學習資源

想深入研究更多指令，可以參考 Git 官方文件、Pro Git 繁體中文教材，以及 GitHub 官方說明文件。建議搭配一個自己的練習專案實際操作，比只看教學更容易建立觀念。

⚠️ 技術操作與資訊安全聲明

本文為 Git 版本控制的入門教學，提供的指令與操作結果可能因作業系統、Git 版本、儲存庫設定、存取權限及遠端服務狀態而有所差異。操作前請先確認目前所在的專案目錄，並妥善備份重要檔案。涉及檔案還原、重設歷史、強制推送或刪除操作時，應先了解指令效果，避免造成資料遺失或團隊版本衝突。請勿將密碼、API Key、Token、個人資料或其他機密內容提交至公開儲存庫。本文範例網址、Commit 識別碼及作者資料均為教學示意，實際使用時請依個人環境調整。
