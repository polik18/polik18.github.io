LINE 無法傳送檔案與照片？系管師實錄：用防火牆 MSS Clamping 破解 MTU 1480 封包黑洞

作者：小黃老師（C樂遊）・發表於 2026-11-16

身為學校的系統管理師，每天面對的除了伺服器還有各種突發狀況。這回體育辦公室老師的求救，看似簡單卻讓人傷透腦筋：LINE 文字傳送正常，但只要傳檔案、照片、影片就狂轉圈圈最後失敗。這篇血淚甘苦談，記錄了我們如何抽絲剝繭，揪出網路傳輸中的「大封包黑洞」，並在不影響全校師生情況下，完美解決 MTU 限制問題的完整過程。

1. 問題現象：LINE 傳檔卡關的靈異事件

「系管師，我們辦公室的電腦怪怪的，LINE 訊息都收得到發得出去，可是怎麼傳照片、文件給主任都傳不過去？」這通來自體育辦公室的電話，開啟了這場除錯之旅。

起初以為只是單純的網路斷線或軟體更新問題，但實際測試發現，網頁瀏覽速度飛快、YouTube 影片播放流暢，甚至連 LINE 裡面的文字聊天都是「秒發秒讀」。唯獨只要涉及檔案傳輸，不管是拖曳圖片還是選擇檔案，進度條就是卡在開頭，最後顯示「傳送失敗」。

這種「半殘」的狀態最難處理，因為它不是完全壞掉，而是挑特定功能壞掉。老師們焦急地等著傳送比賽報名表和訓練影片，我們只好硬著頭皮接下這個任務，誓言找出這到底是哪門子的靈異事件。

2. 核心原因分析：小封包沒事，大封包撞牆

為了找出問題癥結，我們不能只看表面。身為系管師，當然是拿出看家本領——抓封包（Packet Capture）來分析。

經過詳細比對與分析，我們終於發現了癥結所在，原來是「封包大小」惹的禍：

  • 文字聊天 vs. 檔案傳輸： LINE 在傳送純文字時，使用的是極小的封包（約 200～500 位元組），這種小封包在網路上穿梭自如，暢通無阻。但是，一旦你要傳送檔案、照片或影片，LINE 就會自動切換連線到專屬的檔案伺服器，這時候送出來的就是滿載的**「大封包」（標準乙太網訊框大小，約 1500 位元組）**。
  • 對外通道的「大封包黑洞」： 問題來了，經實測發現，學校對外連線到教育局的骨幹通道，有著極為嚴格的限制，通道上限嚴格設定為 1480 位元組（MTU 1480）。這意味著，只要封包大小超過 1480 位元組（哪怕只多 1 個位元組），就會被上游設備視為異常，直接 100% 丟棄（Drop）。
  • IPv6 規範與 Windows 預設值： 更雪上加霜的是，現代網路環境逐漸普及 IPv6。在 IPv6 的規範中，明確禁止網路設備在路徑中途「把過大的封包切碎（Fragment）」。偏偏 Windows 筆電預設就是會送出 1500 位元組的滿載大封包。於是，當老師電腦送出的 1500 byte 封包來到學校對外出口時，撞上了 1480 的隱形天花板，又不能切小，結果就是直接蒸發在網路上，導致傳檔連線徹底卡死，出現無限轉圈圈的窘境。

3. 解決方案：不動終端，直搗核心防火牆

找到原因後，傳統的做法可能是去修改每一台老師電腦的網路設定（修改 MTU 值），但身為追求效率的系管師，怎麼可能做這種苦力活？況且學校那麼多台電腦，萬一又有其他處室甚至學生筆電也遇到同樣問題，豈不是要疲於奔命？

我們的目標很明確：**不更動任何一台終端設備，直接從源頭解決問題。** 我們選擇直接登入全校流量的心臟——核心防火牆（運作在核心層級的 Linux 設備）進行設定修改。

我們在核心防火牆上施展了關鍵的「手術」：

  1. 啟用 TCP MSS 自動限縮（Clamp MSS to PMTU）： 這是最核心的一步。我們在防火牆的 iptables 規則中加入了動態調節的機制。當內網的筆電準備發起連線傳檔時，防火牆會在封包通過閘道的一瞬間，自動將 TCP 連線的 Maximum Segment Size（MSS）強制調降，確保發出的封包大小加上表頭後，絕對不會超過對外通道的 1480 上限。既然貨車（1500 byte 封包）進不去隧道，那就讓它一開始就乖乖改裝成小貨車（小於 1480 byte 的封包）分批載貨，檔案自然就能順利切塊送出去。
  2. 廣播宣告 IPv6 上限（radvd 設定）： 除了 IPv4 的 TCP 流量，針對 IPv6 的流量我們也進行了處理。我們修改了路由器通告（Router Advertisement）的設定，讓核心防火牆主動向全校網段發出廣播：「各位注意！本網路出口的 MTU 上限是 1480，請大家遵守！」這樣一來，Windows 筆電在連線之初，就會自動採用正確的 MTU 值，從源頭避免了大封包撞牆的問題。
  3. 完成永久存檔與備份： 設定完成後，我們謹慎地使用了具備防斷線回滾機制的指令套用設定，並將防火牆規則寫入開機系統區，確保即使未來重開機或遇到無預警停電，設定依然永久生效，守護全校網路暢通。

4. 最終成果與結語：網路暢通的成就感

設定套用完成的那一刻，我們回到體育辦公室，請老師再次試著傳送一份大容量的訓練影片檔案。「咻」的一聲，進度條瞬間從 0% 衝到了 100%，圖片和檔案傳送成功！老師興奮地喊道：「太神了！剛剛還不行的，看來是 LINE 自己修好了！」

我們只是微笑點點頭，深藏功與名。這套解決方案不僅解決了體育辦公室的問題，更是一勞永逸地造福了全校。未來不管是行政處室的電腦，還是各班級的教學用機，甚至是老師們的個人筆電，只要連接上學校網路，使用 LINE、Teams、Google Drive 或其他雲端硬碟傳送大檔案，都不會再發生莫名其妙卡死在封包黑洞裡的問題，即刻恢復正常使用。

作為學校系管師，雖然日常充滿了各種瑣碎的報修與挑戰，但每當能夠運用專業技術，在不打擾使用者工作流程的情況下，悄悄解決難題，看到師生們順利使用網路教學、辦公，心中湧現的那份成就感，就是支撐我們繼續奮鬥的最大動力。網路維運之路，我們仍在繼續！
